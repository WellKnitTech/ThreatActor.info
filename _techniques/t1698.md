## Description

Adversaries may deliver malicious prompts to an LLM indirectly by embedding the prompts in content that the adversary expects may be processed by an LLM. [NIST indirect prompt injection](https://csrc.nist.gov/glossary/term/indirect_prompt_injection) These prompts can be included in web pages, [Palo Alto Indirect Prompt Injection ITW](https://unit42.paloaltonetworks.com/ai-agent-prompt-injection/) documents, emails, tickets, [Snyk Indirect Prompt Injection](https://snyk.io/blog/cline-supply-chain-attack-prompt-injection-github-actions/) code, or other sources that an agent, copilot, or other AI system may retrieve and process. When an LLM processes this content, the embedded instructions may cause the system to perform unintended behaviors. [GTIG AI Threats Sep 2026](https://cloud.google.com/blog/topics/threat-intelligence/from-prompting-to-autonomy-the-evolution-of-adversarial-ai) 

Adversaries may use indirect prompt injection to Impair Autonomous Defenses, and for unauthorized execution of any capabilities available to the LLM.
